# CMS Setup Guide

How to switch on the hidden admin CMS for `meenakshigirish.com`. Do this once.
The CMS code is already merged; these steps provision the secrets it needs.

> **Where things live:** content is stored as JSON in the GitHub repo
> (`src/content/*.json`) and uploaded images under `public/images/cms/`. Every
> CMS save commits to `master`, which triggers a Vercel rebuild (~1 min) — that
> rebuild is what makes the change public. The admin never touches code.

---

## 1. Choose a strong admin password + username

The username and password are the **only** thing protecting content edits, and
the password's hash is the only secret an attacker could not extract even by
downloading the whole site bundle (it's PBKDF2-hashed in a server env var).

- Username: not your email, not "admin". Something unguessable.
- Password: ≥ 20 chars, generated by a password manager. The script below
  rejects anything < 12.

## 2. Generate the password hash (on your own machine)

From the project root:

```bash
node scripts/hash-password.mjs
# → prompts: Admin password:
# → prints:  pbkdf2$150000$<salt>$<hash>
```

Copy the **entire** `pbkdf2$...` string. The plaintext password is now only in
your head — it is not written anywhere by the script.

## 3. Generate a session secret

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Copy the output (≥ 32 chars). If this is ever missing/short, the CMS
**fails closed** — no one can log in and no sessions validate.

## 4. Create a fine-grained GitHub PAT

GitHub → Settings → Developer settings → Personal access tokens →
**Fine-grained tokens** → Generate new token:

- **Repository access:** Only select repositories → `aacharles111/MeenakshiGirish`
  (NOT "all repositories").
- **Permissions:** Repository permissions →
  - **Contents: Read and write**
  - **Metadata: Read** (required)
- Expiration: set whatever you like; you can rotate anytime.
- Generate, copy the `github_pat_…` token.

This token can only touch this one repo's contents. It has no admin/account
rights. If it ever leaks, revoke it here and make a new one.

## 5. (Optional) Vercel deploy-status token

So the admin dashboard can show **Building → Live** after a save:

- Create another fine-grained PAT or use a Vercel token with **project:read**.
- Find `VERCEL_PROJECT_ID` and `VERCEL_ORG_ID` in your local
  `.vercel/project.json` (or the Vercel project dashboard).

If you skip this, the dashboard just shows "Committed — site rebuilds in ~1 min"
after each save. Everything still works.

## 6. Add the env vars to Vercel

Vercel → your project → Settings → Environment Variables (Production):

| Var | Value |
|---|---|
| `ADMIN_USERNAME` | your chosen username |
| `ADMIN_PASSWORD_HASH` | the `pbkdf2$…` string from step 2 |
| `SESSION_SECRET` | the base64 string from step 3 |
| `GITHUB_TOKEN` | the `github_pat_…` from step 4 |
| `GITHUB_REPO` | `aacharles111/MeenakshiGirish` |
| `GITHUB_BRANCH` | `master` |
| `VERCEL_TOKEN` *(optional)* | from step 5 |
| `VERCEL_PROJECT_ID` *(optional)* | from step 5 |
| `VERCEL_ORG_ID` *(optional)* | from step 5 |

(`RESEND_API_KEY`, `ORDER_FROM_EMAIL`, `ORDER_NOTIFY_EMAIL`,
`GOOGLE_SHEET_URL`, `SHEET_SECRET`, `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`
are already set from earlier work.)

**Redeploy** so the new env vars take effect (Vercel → Deployments → Redeploy,
or push any commit).

## 7. Lock down login with Vercel Firewall (recommended)

Vercel → project → Settings → Firewall → add a rate-limit rule:

- **Path:** `/api/admin-login`
- **Limit:** e.g. 10 requests / minute / IP
- **Action:** Block (or Deny)

This caps brute-force guessing on top of the PBKDF2 hash + the ~400ms
per-failed-login server delay.

## 8. First login + smoke test

1. Visit `https://www.meenakshigirish.com/login` (not linked anywhere on the
   site — type the URL). Enter your username + password.
2. You land on `/admin`. The six tabs load the current content from GitHub.
3. **Test a safe edit first:** open **Contact & Socials**, tweak a label, Save.
   You should see Saving → Committed → (Building → Live, if you set the
   Vercel token) and ~1 min later the change is live. The git history
   (`aacharles111/MeenakshiGirish` commits) shows the `[cms] …` commit.
4. **Blog:** create a draft → it's NOT public. Publish it → the **Blog** nav
   link appears and `/blog` lists it. Unpublish/delete → it disappears.
5. **Gallery:** add a photo → after rebuild the Speaking-page dome shows it.
6. Log out → `/admin` bounces to `/login`.

## Security properties (what's protected and how)

- **No secrets in the client bundle.** Username lives server-side; the password
  is PBKDF2-hashed server-side; `SESSION_SECRET` / `GITHUB_TOKEN` are
  server-only env vars. Verify anytime with the grep in the next section.
- **All writes are server-enforced.** Every `/api/cms-*` and `/api/cms-upload`
  verifies the signed `httpOnly` session cookie (HMAC, 8h expiry) and a
  same-origin check. A downloaded bundle grants zero write access.
- **Input is validated** before it's committed (length caps, URL scheme
  allowlists, image type/size caps) and blog bodies are sanitized with
  DOMPurify at render time before `dangerouslySetInnerHTML`.
- **Order amounts are server-validated.** `create-order` recomputes
  `price × copies × 100` from the build-time price and rejects any mismatch, so
  a tampered checkout can't lock in a cheaper order.
- **Hidden, not security.** `/login` and `/admin` are unlinked and
  `robots.txt` disallows them, but hiding is defense-in-depth — the real
  control is the server-side password + signed cookie.

## Secret-leak check (run anytime)

```bash
npm run build
grep -RIn "ADMIN_PASSWORD_HASH\|SESSION_SECRET\|GITHUB_TOKEN\|github_pat_\|RAZORPAY_KEY_SECRET" dist/
# expect: no matches
```

## Rotating secrets

- **Password:** re-run `node scripts/hash-password.mjs`, update
  `ADMIN_PASSWORD_HASH` in Vercel, redeploy. (Old sessions stay valid until
  their 8h expiry or until `SESSION_SECRET` rotates.)
- **Force logout everyone:** change `SESSION_SECRET` in Vercel + redeploy — all
  existing signed cookies become invalid instantly.
- **GitHub PAT:** revoke at GitHub, generate a new fine-grained PAT, update
  `GITHUB_TOKEN`, redeploy.
